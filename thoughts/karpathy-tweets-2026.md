## 一、想法（观点 / 判断 / 预测）

### 1.1 对 LLM 能力的判断

**2026-10-02 — LLM 是否真正理解主题，可用受控英语检验**
Karpathy 建议用 ASD-STE100（航空业受控英语规范，限制词汇和句式）检验 LLM 是否真正理解一个主题。依据：能在受限表达下保持准确性，才说明理解独立于修辞。分类：想法（方法论判断）。

**2026-10-02 — 模型从互联网压缩中获得地理知识**
"Land or Water?" 经纬度评估：向模型询问 16,200 个经纬度点是陆地还是水域，然后绘图。结果证明模型的地理知识来自对互联网文本的压缩学习，而非显式存储地图数据。分类：想法（能力判断）＋工具（评估方法）。

**2026-08 — 评测 LLM 不应停留在简单任务**
给 Opus 5 输入《指环王》首段并给 100 万 token 预算（约 10 美元）生成视频（见 2.2）。Karpathy 的判断：测试 LLM 能力已不该停留在"画骑自行车的鹈鹕"这类简单任务。分类：想法（评测标准）。

### 1.2 LLM 使用模式

**2026-07-22 — "长语音唠叨"模式**
LLM 使用模式出现"长语音唠叨"：切到 /voice，直接说 10 分钟代替打字输入。Karpathy 认为语音长输入成为日常用法。分类：想法（使用模式观察）。

**2026-05-01 — LLM 不只是加速已有流程**
红杉 Ascent 炉边谈话：LLM 不只是加速已有流程，还会催生原本不存在的新流程，举例 menugen（菜单生成类产品）。引用其观点："思考可外包，理解不可外包。"分类：想法（趋势判断）。

**2026-05-12 — 让 LLM 以 HTML/幻灯片输出**
让 LLM 以 HTML 或幻灯片形式输出结果，并在浏览器中查看。分类：想法（交互范式）＋工具（工作流，见 2.4）。

### 1.3 智能体（Agent）时代

**2026-03 — "需要更大的 IDE"**
基本单元正从文件变为智能体；智能体组成的系统可以 fork（复制后独立演化）。判断：现有 IDE 围绕文件设计，跟不上智能体粒度。分类：想法（开发范式预测）。

**2026-03 — "OpenClaw 时刻"**
OpenClaw 时刻：非技术人员第一次体验智能体模型的时间点，类似个人电脑早期的"顿悟时刻"。分类：想法（类比性判断）。

**2026-03 — LLM 记忆的"用力过猛"问题**
评记忆功能：LLM 记忆存在"用力过猛"（over-eager）问题——记太多、不分主次。分类：想法（产品判断）。

**2026-04 — 显式记忆优于"越用越懂你"**
称赞 Farzapedia（显式记忆产物）：显式、用户可查看可编辑的记忆，优于模糊的"越用越懂你"。分类：想法（产品判断）。

### 1.4 社区与平台观察

**2026-04 — "想法文件"（idea file）**
智能体时代，个人分享的最小单位是想法。他提出维护一个"想法文件"，只分享想法本身。分类：想法（传播范式）。

**2026-04 — GitHub 评论质量优于 X**
观察：GitHub 上的评论质量优于 X（Twitter）。分类：想法（平台比较）。

**2026-03 — 评《Project Hail Mary》电影**
对《Project Hail Mary》电影版的评价。分类：想法（评论，非技术）。

## 二、工具（技巧 / 项目 / 工作流）

### 2.1 评估方法

**2026-10-02 — ASD-STE100 检验法**
用 ASD-STE100 受控英语规范作为测试集，检验 LLM 是否真正理解主题。操作：要求模型用受限英语解释主题，观察准确性下降程度。

**2026-10-02 — "Land or Water?" 经纬度评估**
方法：向模型询问 16,200 个经纬度坐标是陆地还是水域，聚合答案后绘图与真实地图对比。用途：探测模型从互联网压缩中学到的隐式地理知识。

### 2.2 生成式项目

**2026-08 — 用 Opus 5 生成《指环王》视频**
操作：给 Opus 5 输入《指环王》开篇第一段，配 100 万 token 预算（约 10 美元），生成视频。产物：karpathy.ai/lotr-movie/。

### 2.3 个人知识管理

**2026-04 — 用 LLM 建个人知识库**
方法：用 LLM 围绕个人研究兴趣构建知识库。该帖数据：21.9M 浏览，108K 收藏。分类：工具（工作流）。

**2026-04 — "想法文件"（idea file）**
操作：维护一个文件，只记录和分享想法，作为智能体时代的最小分享单位。

### 2.4 研究与开发工作流

**2026-03 — autoresearch**
项目地址：github.com/karpathy/autoresearch。定位：配方（recipe）而非工具。工作流：人负责迭代想法，智能体负责跑实验。成果：发现 20 项 nanochat 改进，且可迁移到更大模型。

**2026-03 — 供应链攻击预警**
两次 npm/PyPI 供应链攻击预警：llitellm 与 axios 相关事件。用途：依赖安全告警。

**2026-05-12 — LLM 输出 HTML/幻灯片**
操作：让 LLM 以 HTML 或幻灯片形式输出，在浏览器中查看。用途：比纯文本更适合结构化结果展示。
